# 1. Target .NET 10, not .NET 8

## Context

Minimum supported target is `>= .NET 6`. The obvious safe choice is the LTS most development machines
already have installed.

## Options

- **.NET 8 (LTS)** — the "safe", widely-installed choice.
- **.NET 9 (STS)** — current at the time, but a short-support release.
- **.NET 10 (LTS)** — released Nov 2025, supported to Nov 2028.

## Decision

Target **.NET 10**. Both .NET 8 and .NET 9 reach end of support on **10 November 2026**. Starting new
work on a runtime that is about to go EOL isn't a good baseline, and the `>= .NET 6` floor is
comfortably satisfied either way.

## Consequences

- Visual Studio 2022 cannot target .NET 10/C# 14 — development used VS 2026/Rider/CLI. Worth noting so
  it isn't a surprise on an older IDE.
- Not everyone will have the .NET 10 SDK installed locally. Mitigated by making **Docker the primary
  documented run path** (`docker compose up --build`), verified end-to-end with a clean-clone
  rehearsal.
- Swashbuckle needed pinning to `10.0.0+` (the stack moved to `Microsoft.OpenApi` v2.x, a breaking
  change from the v1.x line that 6.x–9.x depend on).
